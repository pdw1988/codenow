这版原型做了哪些决定
先说最要紧的一条：这里没有 LLM，也不该有。
这是本地离线工具，同一段日志进去必须每次出一模一样的 SQL——这是它值得被信任的全部理由。 接了大模型就成了「大概率对」，而这个功能错了是不报错的：参数错位的语句照样能跑，只是数据是错的。 所以我做的是对话式的交互范式 + 科技感的视觉，解析仍然是 lib/sqlgen/logFill.ts 那套确定性规则。 如果你要的是真接 API 的那种，那是另一个方向，你说一声。
为什么聊天范式在这个功能上是真的更好

不是为了跟风。现在那张参数对照表在弹窗里，点掉就再也看不见了——而它是这个功能可信度的唯一来源。 改成对话流之后它变成回答卡片的一部分，永久留在历史里，随时能翻回去核对。这修掉的是一个真实缺陷。

  • 历史不再丢。现在贴第二段日志，第一段的结果就没了。对话流天然保留，顶部会话条还能跳回去。
  • 「改一下」有地方说了。换方言、改某个参数、批量里只要第 2 条——现在得回去改输入框重新识别。
  • 失败也是一条消息。认不出来的时候给一张卡片说清楚「我认得哪几种」，而不是弹一个转瞬即逝的 toast。
保留下来的东西（一个都没丢）
  • 粘贴即识别，不给「解析」按钮。输入只有一种来源，多一次点击没意义。
  • 参数对照表四列不变：第几个 ? / 日志里的原样文本 / 值（可改） / 进 SQL 的样子。
  • 值可改，改完 SQL 实时重算（这里是真算的，你可以试）。
  • 个数对不上照样出结果，但整卡标红，缺的那几行单独标出来。宁可让人当场看见。
  • 5 种日志格式、4 种方言（Oracle 打头）、批量多条各自可复制。
改掉的东西
  • 确认弹窗没了。它的职责（核对）由常驻的对照表接管，而且比弹窗更持久。少一次「确认生成」的点击。
  • 左右分栏没了。日志作为「你说的话」折叠在上面（默认只露 3 行，点开看全），SQL 是「回答」。 纵向阅读比左右对照更符合「贴进去→拿结果」的实际动作。
  • 方言从卡片里提到顶栏，因为它是全局的，且改了要影响历史里所有卡片的重算。
  • 「视觉浓度 强/弱」那个开关没了。见下条。
视觉：从两档浓度换成 5 套整体样式

上一版左下角是个「强 / 弱」开关，两档差别小、还漏了几处写死的青色，切过去有一块是花的， 等于没得选。现在换成右上角（或左栏底部、数字键 1–5）5 套完整方案， 不只是配色变，圆角、字体、发光、背景层、标签大小写全都跟着换：

  • 深空霓虹　深蓝黑 + 霓虹青 + 网格 + 扫描线 + 毛玻璃 + HUD 角标（就是原来的「强」）
  • 石墨　　　中性深灰 + 钢蓝，平面、无发光、小圆角，最克制的一套
  • 终端磷光　纯黑 + 磷绿，全站等宽字体、直角、CRT 扫描线
  • 蓝图　　　墨蓝 + 密网格 + 琥珀描线，细线直角，工程图纸感
  • 霓虹紫　　紫洋红渐变 + 强发光 + 大圆角

样式只有一份实现（mockup/_theme.css），6 个功能页共用，所以同一个组件在每页长得一样， 挑样式才挑得准。组件规则一律只读 CSS 变量——写死一处颜色，5 套里就有 4 套是坏的， 而且只有切过去才看得见。左栏「样式总览」那页能 5 套并排看。

「打字追问」怎么可信

固定意图表，不猜。认得的就做，认不得就明说认不得并列出词表——绝不给一个似是而非的结果。 当前词表：换成 Oracle/MySQL/PG、第 N 个参数改成 X、只要第 N 条、复制。 试试打「导出成 Excel」看它怎么拒绝。

还没定、想听你意见的
  • 5 套里挑哪一套（或者说哪一套的哪部分）。挑定了我把其余 4 套删掉，只留一份。
  • 这套对话流要不要推广到别的 Tab：其余 5 个页面这一轮做成了面板式。SQL 生成器配置项多， 聊天流未必比「左边配置右边出结果」好。我倾向只有日志转 SQL 和未来的自然语言查询用对话流。
  • 是否保留「确认」这一步：我这版取消了。如果你觉得少了一道闸不放心， 可以改成「生成即出，但顶部有一条未核对的提示条，点『我核对过了』才消失」。
