写新代码先问一句：这段能不能不带 React 写？能，就落 lib/；不能，才进 features/。
两条数据流
互不依赖
主流 · 表结构 → SQL
粘贴 CREATE TABLE  features/importer/DdlImport
  → lib/oracleDdl   无条件预处理：摘 comment on、换 Oracle 类型词、
                    砍 tablespace（对纯 MySQL 是恒等变换，不用先猜方言）
  → lib/ddlParser   node-sql-parser AST → TableInfo[] + ForeignKey[]
  → useSchemaStore.importTables() → MetaStore → cache.db
  → lib/search      PRD 3.4 的 7 条匹配规则（含拼音首字母）
  → useUiStore.jumpToSqlGen({tableName, relatedTables})
                    ← 跨 Tab 传上下文只走这一个口子
  → lib/sqlgen/*    useMemo 实时重算，没有「生成」按钮
第二条 · 日志转 SQL（不碰表结构缓存）
粘贴日志  onPaste 里从 clipboardData 取，不读 textarea.value
  → logFill.parseLog    5 种日志格式 → LogStatement[]
  → 参数对照表（第几个 ? 拿了哪个值、进 SQL 长什么样，可改）
  → buildFilledSql → renderFilled   全纯函数，47 条单测钉边界
这条流故意不依赖缓存：随手粘一段日志就能用，没导过表也不空手。 所以它不准去读 useSchemaStore —— 一旦读了， 「没导表也能用」这个卖点就没了。

零自定义 command，前端也没有一处 invoke。SQL 由 @tauri-apps/plugin-sql 的 JS 侧直发 （Database.load('sqlite:cache.db') → plugin:sql|execute），Rust 只管注册插件、跑 migration、发权限。 要往 Rust 加东西，先问能不能不加 —— 加了就得能编译，而现在编不了（见右下）。
落盘路径没人验证过。插件按 identifier 走，实际应该是 %AppData%\com.pdw.devtools\cache.db，而 lib.rs 注释里写的是 PRD 要求的 %AppData%\DevTools\ —— 两者不一致，因为 Rust 侧一次都没跑起来。
缓存库结构
migration v1
表存什么关键约束
cached_tables表名 / 注释 / Java 类 / 来源 table_name UNIQUE，故意不带 data_source
cached_columns字段全属性 + Java 映射 FK → cached_tables，ON DELETE CASCADE
cached_foreign_keys外键，带可信度 confidence = constraint / naming，四列联合 UNIQUE
cache_metadatakey-value JSON 模板、最近查询 —— 不值得建表的都塞这
两处对 PRD 6.3 的有意偏差：① 唯一键不带 data_source —— 前端按表名寻址，允许同名表来自两个库会让 「查 user 表」变成一个有歧义的问题；② 暂不建 FTS5 虚表 —— 50~100 张表在内存里 线性扫描是微秒级，且还没确认打包的 SQLite 开了 fts5 编译选项。
改表结构只能新增 Migration{version:2}， 不准改 v1 的 SQL —— 已经建过库的机器不会重跑 v1。而本机缺链接器，动 migration 等于 改了也验证不了，所以新持久化数据一律先考虑塞 cache_metadata， 模板功能就是这么做的。
写代码时的硬规矩
每条都踩过一次
方言差异只准写在 dialect.ts 的 DialectSpec 里。在调用点写 dialect === 'oracle' ? … : …，同一条规则就有两份，然后只修好一份。
拼 WHERE 一律复用 executable.renderCondition()：空值是 IS NULL，永远不是 = NULL —— 后者恒为 unknown，查不出、删不掉，还不报错。
自动造的值不进 state，只留用户手改过的那几个。存一整份等于埋一个 「表结构变了但值还是旧的」不一致点。
props 变化重置 state 用渲染期校正，不用 useEffect + setState（oxlint 的 react(set-state-in-effect)，且 effect 版会先用旧值闪一帧）。
启动期读数据必须 await initStore()，不能直接 getStore() —— 初始化完成前它返回的是 MemoryStore， 在 Tauri 里会读到 localStorage 而不是 SQLite。
antd 是 6 不是 5：API 改名 + DOM 类名全变。照 v5 写的 Tab 布局规则 曾经一条都没命中、整页跟着滚，而四道闸门全绿 —— 改样式后要在真浏览器里数命中。
注释写为什么不写做了什么；测试用例名对应一个真踩过的坑。
验证
刚跑过
✅ pnpm typecheck ✅ pnpm lint ✅ pnpm test · 173 ✅ pnpm build · 2.3s
四道闸门证明不了「生成的 SQL 能跑」。项目里最狠的几个 bug —— 逗号被行尾注释吃掉、多表列名撞车导致 ResultSet 静默覆盖、注释里的单引号每次往返翻倍 —— 都是四绿之后才发现的。所以另外三件事是硬要求：
node:sqlite DatabaseSync(':memory:') 真执行生成的 DDL / SQL
往返解析 导出的 DDL 再喂回 parseDdl，断言信息无损
e2e.mjs Node 内置 WebSocket 驱动 CDP，无 puppeteer，点真浏览器
断言要挑能证伪的量：模板那段不是「列表里多了一条」，而是 存 → 改配置让 SQL 变短 → 套用 → 字符数回到存的时候。

这一轮的取舍

能自动就不让你确认
砍掉的点击
导入表结构：原来是 粘贴 → 点「解析」→ 看预览 → 点「导入 N 张表」。 现在粘贴一步到位，右边同时是预览和结果，出错用常驻的撤销兜底。
SQL 生成：本来就没有「生成」按钮。这次连值面板也改成边改边重算， 改一个字符右边就变。
JSONPath：粘贴时自动格式化，去掉「格式化 / 填示例」两个按钮； 进页面就带着示例 JSON 和一条表达式。
表结构速查：边打边搜，命中第一名的表直接展开字段表 —— 搜到了还要再点一下才能看，等于白搜一趟。
正则测试：预设点一下连测试文本一起换，不用自己造样本。
哪些地方故意保留了一次确认
命名推断的外键默认不勾。xxx_id 推出来的关系可能是错的，默认让它参与 JOIN 等于悄悄生成错 SQL —— 这一次勾选必须由你来点。
可执行 SQL 上方常驻提醒。值是自动造的，语句能直接跑， 所以「执行前确认它不会打乱现有数据」这句话不能省。
分界线：只影响显示的，自动做；会改到数据库的，让你看清楚。
