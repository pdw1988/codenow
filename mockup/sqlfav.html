详情与复用
设计取舍 · 待你拍板 规格没写死的缝，只有这五条
1. 要不要加「最常用」排序：§6.5 只点名了「最近使用」，但 use_count 就在 §6.8 的表结构里——不加白存了。原型已带上，砍掉是一行事。
2. 表名自动识别的精度：现在抓 FROM/JOIN/UPDATE/INTO 后面的标识符 （库名前缀取末段）。别名、子查询会抓不全，information_schema 这类系统视图也会被当表名 认出来（识别后可清空手改）。够不够？
3. 导入冲突策略：现在是「名称+SQL 都相同才跳过」，id 不参与比对。 要不要改成按 id 覆盖？倾向不——跨机器的 id 本来就不保证一致。
4. 「编辑 → 跳转生成器」怎么带内容（§6.7）：收藏的多是能直接跑的成品， 硬灌进预编译/可执行配置都不合适。倾向：跳过去落在一个只读大输入框 + 复制按钮， 不强行映射成生成器配置。
5. 团队共享库：商业化条款里团队版的卖点，本地单机版不做同步。
